# Windows 11 배포 검수 체크리스트

이 문서는 자동화 테스트 결과가 아니라 최종 배포 환경에서 사람이 확인하고
증거를 남기는 체크리스트입니다. 실제로 확인한 항목만 체크하십시오.

## 패키지와 환경

- [ ] `dist\ArubaMiniDashboard` onedir 폴더 전체를 검수 PC에 복사함
- [ ] Windows 11 x64 일반 사용자 계정이며 관리자 권한 없이 검수함
- [ ] Python이 설치되지 않은 깨끗한 PC/VM에서 검수함
- [ ] 인터넷 차단 상태이며 승인된 사내 SSH 경로만 허용함
- [ ] 로컬 일반 경로에서 `ArubaMiniDashboard.exe`가 추가 설치 없이 실행됨
- [ ] 한글·공백 포함 경로에서도 배포 폴더를 손상 없이 실행함
- [ ] 배포 SHA-256이 빌드 시 생성된 값과 일치함
- [ ] 배포 폴더에 `.py`, `.pyc`, `.db`, `.log`, `.cred`, `.key`가 없음

참고: 패키지 verifier는 Python 환경변수/PATH를 제거한 로컬 smoke에서
Netmiko·Paramiko·Windows Credential Manager, 동결 fixture 탐색, 데모
파싱·종합 판단 1회를 검증합니다. 그래도 실제 Python 미설치 clean VM
확인을 대신하지 않습니다.

## 첫 실행과 설정

- [ ] 첫 실행 시 메인 창이 열리고 자동 점검은 일시정지 상태임
- [ ] `설정`을 열어 MM, WLC 4개, Primary/Fallback, timeout과 주기를 저장함
- [ ] 점검 주기 10~3,600초 경계값과 잘못된 값의 한글 오류를 확인함
- [ ] 공통 계정과 MM/WLC 별도 계정을 각각 확인함
- [ ] Credential Manager 영구 계정을 저장하고 프로그램 재시작 후 사용함
- [ ] 세션 전용 계정이 실행 중에는 동작하고 재시작 후 재입력을 요구함
- [ ] 설정 JSON과 SQLite에 사용자명·비밀번호·Enable Secret이 평문으로 없음
- [ ] 손상된 설정 파일을 덮어쓰지 않고 자동 점검을 중지하며 오류를 표시함

## SSH 지문과 안전 경계

- [ ] 자격 증명 전송 전에 MM SSH SHA-256 지문 승인을 요구함
- [ ] Primary와 응답 가능한 각 Fallback의 지문을 독립적으로 확인함
- [ ] Primary 지문 스캔 실패 시 다음 Fallback의 지문 확인을 계속함
- [ ] 저장된 값과 다른 지문을 자동 승인·교체하지 않고 접속을 차단함
- [ ] 세 show 명령, 선택적 `enable`/`no paging` 외 명령이 실행되지 않음을
      장비 감사 로그 또는 승인된 시험으로 확인함
- [ ] 앱이 장비 설정 모드에 진입하거나 구성을 저장·변경하지 않음을 확인함

## 수집과 Failover

- [ ] `지금 점검`, 자동 시작, 일시정지와 다음 점검 시각이 정상임
- [ ] SSH 실행 중에도 창 이동·크기 조절·세부/설정 화면이 응답함
- [ ] 점검 도중 다음 주기가 와도 SSH 점검이 중복 실행되지 않음
- [ ] Primary 실패 시 설정 순서로 Fallback하고 실제 수집 IP와 시각을 기록함
- [ ] 한 Controller의 부분 결과와 다른 Controller 결과를 섞지 않음
- [ ] 모든 수집 Controller 실패 시 Cluster 상태가 확인 불가로 표시됨
- [ ] MM 인증 실패, timeout, 빈 출력과 파싱 실패가 WLC Down으로 표시되지 않음

## 실제 출력과 판단 규칙

- [ ] 실제 `show switches` 출력에서 모든 Up, 한 IP Down, 복수 Down을 확인함
- [ ] Down 이후 신뢰 가능한 Up 행이 확인될 때만 복구 알림이 발생함
- [ ] 실제 Client 출력의 쉼표 숫자와 네 구성원 행을 정확히 파싱함
- [ ] Client 1회 저하는 알림이 없고 기본 3회 연속 저하에서 활성화됨
- [ ] 전체 Active 사용량이 낮을 때 특정 IP 장애를 만들지 않음
- [ ] 기본 2회 정상 값 이후 Client 이상 복구를 기록함
- [ ] 출력 행 누락은 기본 3회 후 별도 경고이며 파싱 실패와 구분됨
- [ ] Connection-Type 최초 수집은 알림 없이 baseline만 저장함
- [ ] Connection-Type 변경, 원복, 다른 값 변경을 각각 별도 사건으로 기록함
- [ ] 재시작 뒤 baseline, streak, 사건과 확인 여부를 유지함
- [ ] 같은 IP의 두 이상이 장애로 승격되고 서로 다른 IP는 모두 표시됨
- [ ] 일부 명령만 실패하면 성공 데이터와 실패 원인을 함께 표시함

실제 출력 fixture에는 IP, Hostname, 사용자명과 고객 식별자를 제거한 뒤 장비
모델, ArubaOS 버전, 명령 이름과 수집 조건을 별도 기록하십시오.

## UI와 화면 배율

- [ ] 100% 배율에서 상단 요약, 표, 설정과 세부 화면의 한글이 잘리지 않음
- [ ] 125% 배율에서 상단 요약, 표, 설정과 세부 화면의 한글이 잘리지 않음
- [ ] 150% 배율에서 상단 요약, 표, 설정과 세부 화면의 한글이 잘리지 않음
- [ ] 최소 크기와 확대한 크기에서 스크롤·크기 조절이 정상임
- [ ] 항상 위 변경 후 창 위치와 크기가 유지되고 재시작 후 복원됨
- [ ] 투명도 40~100%, 숫자 표시, 마우스 휠 차단, 기본값 복원이 정상임
- [ ] 문제 IP/행을 선택해 근거, 이전 값, streak, 오류와 파싱 결과를 확인함
- [ ] 최근 원본의 인증 프롬프트가 마스킹되고 비밀번호가 표시되지 않음

offscreen scale 자동화는 layout 계산 회귀 검사이며 실제 디스플레이·글꼴·DPI
시각 검수의 대체 증거가 아닙니다.

## 트레이와 알림

- [ ] 트레이 아이콘으로 창 열기·숨기기·종료가 정상임
- [ ] X 버튼은 트레이 사용 가능 시 창만 숨기고 감시를 계속함
- [ ] 트레이 사용 불가 환경에서 X 버튼이 안전한 종료를 요청함
- [ ] Windows 알림 테스트와 알림음 테스트가 정책 허용 환경에서 동작함
- [ ] 신규 장애 즉시 알림과 같은 IP/원인의 중복 방지가 정상임
- [ ] 반복 알림 사용 시 설정 간격 전에 반복되지 않음
- [ ] `알림 확인` 후 반복은 중지되지만 감시는 계속됨
- [ ] 복구 알림 설정에 따라 복구 사건과 알림이 정확히 처리됨
- [ ] 트레이/Windows 알림 비활성 환경에서도 프로그램이 종료되지 않음

## 파일, 로그와 종료

- [ ] `%LOCALAPPDATA%\ArubaMiniDashboard`에 설정, DB와 로그가 생성됨
- [ ] `app.db`에 원본 명령 출력과 credential blob이 없음
- [ ] 일반 로그에 장비 명령 원문과 비밀번호·Enable Secret이 없음
- [ ] SSH 디버그를 켜고 끌 수 있으며, 기록은 제한된 마스킹 excerpt임
- [ ] 로그가 파일당 5MB, 백업 최대 5개로 회전함
- [ ] 설정 저장 실패나 SQLite lock에도 현재 화면이 종료되지 않음
- [ ] 종료 중 점검 작업을 취소하고 SSH 세션을 닫음
- [ ] 종료 후 백그라운드 프로세스가 남지 않음

검수 결과에는 화면 캡처, SHA-256, Windows/ArubaOS 버전, 비식별 fixture와
실패 시 사용자 표시 문구·오류 코드를 첨부하십시오. 비밀번호, SSH 개인키,
실제 운영 IP/Hostname과 원본 출력은 승인 없이 증거 파일에 포함하지 마십시오.
