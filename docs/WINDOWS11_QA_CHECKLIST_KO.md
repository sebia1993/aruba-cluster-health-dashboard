## 패키지와 환경

- [ ] `dist\ArubaMiniDashboard` onedir 폴더 전체를 검수 PC에 복사함
- [ ] Windows 11 x64 일반 사용자 계정이며 관리자 권한 없이 검수함
- [ ] Python이 설치되지 않은 깨끗한 PC/VM에서 검수함
- [ ] 배포 runtime이 CPython 3.13.15 Windows x64 표준 GIL 빌드이며 실험적
      free-threaded(`3.13t`) runtime이 아님
- [ ] 인터넷 차단 상태이며 승인된 사내 SSH 경로만 허용함
- [ ] 로컬 일반 경로에서 `ArubaMiniDashboard.exe`가 추가 설치 없이 실행됨
- [ ] 한글·공백 포함 경로에서도 배포 폴더를 손상 없이 실행함
- [ ] 배포 SHA-256이 빌드 시 생성된 값과 일치함
- [ ] `LICENSE.txt`가 포함되고 루트 MIT `LICENSE`와 바이트 단위로 동일함
- [ ] `.py`는 manifest에 고정된 `_internal\PySide6\__init__.py`,
      `_internal\shiboken6\__init__.py`, `_internal\paramiko\*.py`,
      `_internal\scp.py`에만 존재하고 `.pyc`, `.db`, `.log`, `.cred`, `.key`가 없음
- [ ] `THIRD_PARTY_NOTICES.txt`가 포함되고 비어 있지 않음
- [ ] `PERFORMANCE_REPORT_KO.md`가 포함되고 기준선·미측정 범위를 명확히 구분함
- [ ] `QT_THIRD_PARTY_NOTICES.txt`, `QT_RUNTIME_INVENTORY.json`,
      `LGPL_RUNTIME_INVENTORY.json`, `LGPL_RUNTIME_LICENSES\`,
      `LGPL_RUNTIME_REPLACEMENT_KO_EN.md`가 포함됨
- [ ] `LGPL_RUNTIME_INVENTORY.json`에서 PySide6/shiboken6/Paramiko/scp가
      external source이고 PYZ 내부 감지 목록이 비어 있음
- [ ] Qt Virtual Keyboard/PDF/QML/Quick/OpenGL 미사용 구성 요소가 없고, Qt 번역은
      `qt_ko.qm`과 `qtbase_ko.qm`만 포함됨
- [ ] Netmiko 장비 드라이버와 Paramiko는 유지되며, 배포 실행에 불필요한
      Netmiko CLI 도구와 rich/ruamel/markdown-it/pygments가 PYZ에 없음
- [ ] EXE 속성의 제품명·설명·원본 파일명·버전이 전달 버전과 일치함

참고: 패키지 verifier는 Python 환경변수/PATH를 제거한 로컬 smoke에서
Netmiko·Paramiko·Windows Credential Manager, 동결 fixture 탐색, 데모
파싱·종합 판단 1회를 검증합니다. 그래도 실제 Python 미설치 clean VM
확인을 대신하지 않습니다.

## 첫 실행과 설정

- [ ] 필수 설정이 없는 첫 실행에서 메인 창과 첫 실행 설정창이 자동으로 열림
- [ ] `나중에 설정`으로 닫으면 `설정 필요` 안내가 남고 지금 점검·자동 시작은
      비활성화되지만 설정창과 트레이 종료는 사용할 수 있음
- [ ] 설정창이 `장비·자격 증명`, `운영`, `알림` 3개 탭으로 구성되고 고급 연결,
      감지 기준, 반복 알림·진단 항목이 접힌 영역에 있음
- [ ] 설정 항목의 이름이나 입력란에 마우스를 올리면 용도·기본값·주의사항을
      설명하는 도움말이 표시됨
- [ ] MM, WLC 4개와 Primary를 저장하면 Fallback이 나머지 등록 순서로 구성됨
- [ ] 첫 실행 설정 저장 시 지문 확인과 로그인만 자동 실행하고 show 명령 수집이나
      자동 점검은 시작하지 않으며, 메인 화면의 `지금 점검`으로 첫 수집을 시작함
- [ ] 이후 설정에서 timeout과 점검 주기를 변경하고 정상 저장함
- [ ] 점검 주기 10~3,600초 경계값과 잘못된 값의 한글 오류를 확인함
- [ ] 공통 계정과 MM/WLC 별도 계정을 각각 확인함
- [ ] Credential Manager 영구 계정을 저장하고 프로그램 재시작 후 사용함
- [ ] 세션 전용 계정이 실행 중에는 동작하고 재시작 후 재입력을 요구함
- [ ] 설정 JSON과 SQLite에 사용자명·비밀번호·Enable Secret이 평문으로 없음
- [ ] 손상된 설정 파일을 덮어쓰지 않고 자동 점검을 중지하며 오류를 표시함

## SSH 지문과 안전 경계

- [ ] 자격 증명 조회·전송 전에 MM과 응답 가능한 Controller의 SSH SHA-256
      지문을 한 화면에서 일괄 확인함
- [ ] 승인한 여러 지문을 앱 전용 known_hosts에 원자적으로 기록함
- [ ] Primary 지문 스캔 실패 시 다음 Fallback의 지문 확인을 계속함
- [ ] 저장된 값과 다른 지문을 자동 승인·교체하지 않고 접속을 차단함
- [ ] MM과 최소 1대 Controller 로그인 성공 시 나머지 실패를 Fallback 준비
      미완료 경고로 표시하고, MM 또는 모든 Controller 실패 시 저장하지 않음
- [ ] 운영·알림 등 비연결 설정만 바꾸면 SSH 접속 없이 저장하고, 전체 재확인은
      `고급 진단 > 연결 다시 확인`에서 실행함
- [ ] 구형 ArubaOS에서 Paramiko 5.0.0의 KEX·호스트 키·서명 알고리즘 협상을
      확인하고, 실패 시 원문 예외나 장비 정보 없이 `SSH_ALGORITHM_INCOMPATIBLE`로 표시됨
- [ ] 알고리즘 비호환을 우회하기 위해 약한 legacy 알고리즘을 자동 활성화하지 않음
- [ ] 세 show 명령, 선택적 `enable`/`no paging` 외 명령이 실행되지 않음을
      장비 감사 로그 또는 승인된 시험으로 확인함
- [ ] 앱이 장비 설정 모드에 진입하거나 구성을 저장·변경하지 않음을 확인함

## 수집과 Failover

- [ ] `지금 점검`, 자동 시작, 일시정지와 다음 점검 시각이 정상임
- [ ] SSH 실행 중에도 창 이동·크기 조절·세부/설정 화면이 응답함
- [ ] 점검 도중 다음 주기가 와도 SSH 점검이 중복 실행되지 않음
- [ ] Primary 실패 시 설정 순서로 Fallback하고 실제 수집 IP와 시각을 기록함
- [ ] 한 Controller의 부분 결과와 다른 Controller 결과를 섞지 않음
- [ ] 모든 수집 Controller 실패 시 Cluster 상태가 확인 불가로 표시됨
- [ ] MM 인증 실패, timeout, 빈 출력과 파싱 실패가 WLC Down으로 표시되지 않음
- [ ] 취소 또는 종료 요청 시 재시도 대기가 즉시 해제되고 연결 중인 TCP socket과
      활성 SSH 전송을 닫음
- [ ] 종료 중 GUI가 응답하며 worker thread나 프로세스를 강제로 종료하지 않고,
      정리 완료 뒤 앱 프로세스와 `aruba-active-ssh-cancel` thread가 남지 않음

## 저사양 모드와 성능

- [ ] 일반 모드가 기본값이며 기존 설정 파일에 `performance` 항목이 없어도
      일반 모드·성능 로그 꺼짐으로 정상 로드됨
- [ ] 저사양 모드에서 10~119초로 설정한 자동 점검 주기는 실제 120초로 적용됨
- [ ] 저사양 모드에서 120초 이상으로 설정한 주기는 그대로 적용됨
- [ ] 저사양 모드에서도 `지금 점검`은 예약 주기를 기다리지 않고 즉시 실행됨
- [ ] 저사양 모드에서 MM과 클러스터 수집이 최대 두 작업으로 겹쳐 실행되며,
      느린 MM 응답이 클러스터 상태 수집 시작을 지연시키지 않음
- [ ] 저사양 모드에서도 한 점검 안의 장비 수집 동시 작업이 두 개를 넘지 않음
- [ ] 같은 fixture 또는 승인된 현장 출력으로 일반 모드와 저사양 모드의 파싱,
      감지 사건, 문제 IP와 최종 심각도가 동일함
- [ ] 압축 효과가 높은 원본 출력은 정확히 복원되고, 효과가 낮은 출력은 원문으로
      유지되며, 손상된 한 항목이 다른 명령 출력 표시를 막지 않음
- [ ] 저사양 모드의 전체 장비가 250대를 넘으면 전체 정렬 후 250대 단위로
      표시되고, 이전·다음 이동과 장비 선택 복원이 정확함
- [ ] 저사양 모드와 실제 자동 점검 간격이 메인 화면에 계속 표시되며, Demo에서
      바꾼 값은 현재 Demo 실행에만 적용된다고 안내됨
- [ ] 창을 트레이로 숨긴 동안 표가 계속 다시 그려지지 않고, 다시 열면 가장
      최근 결과가 한 번에 표시됨
- [ ] 점검 중 반복 클릭으로 점검 coordinator worker가 중복 생성되지 않으며
      앱 전용 Qt worker 풀의 동시 점검은 1개로 제한됨
- [ ] 선택적 성능 로그가 기본적으로 생성되지 않고, 켰을 때만
      `logs\performance.log`에 집계 시간·개수가 기록됨
- [ ] 성능 로그에 IP, Hostname, 사용자 ID, 비밀번호, Enable Secret, credential ID,
      원본 명령 출력이 없음
- [ ] 성능 로그가 1MB, 백업 최대 2개로 회전하고 옵션을 끈 뒤 추가 기록이 없음
- [ ] 동일 조건에서 일반/저사양 모드의 시작 시간, 유휴 CPU, 메모리, 점검 시간,
      네트워크 요청 횟수와 디스크 쓰기를 각각 기록함
- [ ] 저전력 CPU·4~8GB RAM·SATA SSD 또는 HDD 환경에서 UI가 응답 없음 상태가
      되지 않으며 장시간 운전 후 스레드·핸들·메모리가 지속 증가하지 않음

실제 저사양 PC, HDD cold start, 느린 Aruba SSH와 24시간 이상 soak를 실행하지
않았다면 통과로 표시하지 말고 `PERFORMANCE_REPORT_KO.md`의 미측정 항목으로
남기십시오.

## 실제 출력과 판단 규칙

- [ ] 실제 `show switches` 출력에서 모든 Up, 한 IP Down, 복수 Down을 확인함
- [ ] Down 이후 신뢰 가능한 Up 행이 확인될 때만 복구 알림이 발생함
- [ ] 실제 Client 출력의 쉼표 숫자와 네 구성원 행을 정확히 파싱함
- [ ] Client 1회 저하는 알림이 없고 기본 3회 연속 저하에서 활성화됨
- [ ] 전체 Active 사용량이 낮을 때 특정 IP 장애를 만들지 않음
- [ ] 기본 2회 정상 값 이후 Client 이상 복구를 기록함
- [ ] 출력 행 누락은 기본 3회 후 별도 경고이며 파싱 실패와 구분됨
- [ ] Connection-Type 최초 수집은 알림 없이 baseline만 저장함
- [ ] Connection-Type 변경, 원복, 다른 값 변경을 각각 별도 사건으로 기록함
- [ ] 재시작 뒤 baseline, streak, 사건과 확인 여부를 유지함
- [ ] 같은 IP의 두 이상이 장애로 승격되고 서로 다른 IP는 모두 표시됨
- [ ] 일부 명령만 실패하면 성공 데이터와 실패 원인을 함께 표시함

실제 출력 fixture에는 IP, Hostname, 사용자명과 고객 식별자를 제거한 뒤 장비
모델, ArubaOS 버전, 명령 이름과 수집 조건을 별도 기록하십시오.

## UI와 화면 배율

- [ ] 100% 배율에서 상단 요약, 표, 설정과 세부 화면의 한글이 잘리지 않음
- [ ] 125% 배율에서 상단 요약, 표, 설정과 세부 화면의 한글이 잘리지 않음
- [ ] 150% 배율에서 상단 요약, 표, 설정과 세부 화면의 한글이 잘리지 않음
- [ ] 360x260과 기본 420x320에서 등록 WLC 4대의 상태·분배·마지막 점검이 가로 스크롤 없이 표시됨
- [ ] 폭 900px 미만은 간단 보기, 1,000px 이상 또는 최대화는 전체 보기이며 경계에서 반복 전환하지 않음
- [ ] 간단 보기에는 등록 WLC만, 전체 보기에는 미등록 장비도 `감시 제외`로 표시됨
- [ ] 미등록 장비의 Down·누락이 전체 상태, 문제 IP와 알림을 변경하지 않음
- [ ] 항상 위 변경 후 창 위치·크기·최대화 상태가 유지되고 재시작 후 복원됨
- [ ] 이전 모니터를 제거하거나 배율·작업 영역을 바꾼 뒤 복원된 메인 창이 현재
      모니터의 사용 가능한 영역 안에 표시됨
- [ ] 설정·장비 상세·UI 요소 정보·요소 목록 창이 100%/125%/150%와 다중
      모니터에서 화면 밖으로 잘리지 않고 최소 조작 영역을 유지함
- [ ] 투명도 40~100%, 숫자 표시, 마우스 휠 차단, 기본값 복원이 정상임
- [ ] 설정 숫자·감지 모드는 hover/Tab 휠로 바뀌지 않고 직접 클릭 후 휠로만 변경됨
- [ ] 설정 입력의 직접 입력·증감 버튼·키보드·목록 선택이 정상이며 포커스 이탈 후 휠이 다시 잠김
- [ ] 문제 IP/행을 선택해 근거, 이전 값, streak, 오류와 파싱 결과를 확인함
- [ ] 최근 원본의 인증 프롬프트가 마스킹되고 비밀번호가 표시되지 않음

offscreen scale 자동화는 layout 계산 회귀 검사이며 실제 디스플레이·글꼴·DPI
시각 검수의 대체 증거가 아닙니다.

## 개발자 UI 식별 모드

- [ ] 일반 실행과 `--demo` 실행이 모두 일반 사용자 모드로 시작하고, F12를
      누르기 전에는 개발자 표시줄·식별 테두리·요소 정보가 보이지 않음
- [ ] 개발자 모드를 켠 뒤 프로그램을 정상 종료하거나 강제 종료해 다시 실행해도
      항상 비활성화되며 설정 JSON·SQLite·레지스트리에 활성 상태가 저장되지 않음
- [ ] 애플리케이션 창에 포커스가 있을 때 수정 키 없는 직접 F12 한 번으로 켜지고,
      다시 F12를 누르면 선택 중인 상태까지 취소하며 완전히 꺼짐
- [ ] Ctrl+F12, Shift+F12, Alt+F12와 키 자동 반복은 개발자 모드를 전환하지 않음
- [ ] `--ui-inspector` 같은 명령줄 인수, `ARUBA_UI_INSPECTOR` 같은 환경 변수,
      설정 파일, 일반 메뉴와 트레이 메뉴로 개발자 모드를 활성화할 수 없음
- [ ] 개발자 표시줄의 `종료`는 켜진 모드를 끄기만 하며 꺼진 모드를 켤 수 없음
- [ ] `요소 선택` 중 등록 요소 위에 식별 테두리가 정확히 표시되고, 클릭하면
      한국어 이름·고정 UI 식별자·화면 위치·저장소 상대 소스 위치·용도가 열림
- [ ] 요소 선택 중 버튼, 표 행·머리글, 탭과 메뉴 항목을 클릭해도 원래 클릭·
      선택·정렬·탭 전환·메뉴 명령이 실행되지 않고 요소 정보만 열림
- [ ] 요소 선택 중 Esc를 누르면 선택과 테두리만 취소되고 개발자 모드는 계속
      켜져 있으며, 선택 중이 아닐 때의 기존 Esc 동작을 가로채지 않음
- [ ] `요소 목록`에서 고정 식별자가 중복 없이 표시되고, Windows 네이티브
      트레이 메뉴 항목도 화면 직접 선택 대신 정적 카탈로그로 확인할 수 있음
- [ ] `작업 요청 복사` 결과가 프로그램 버전·정적 화면 위치·요소 이름·UI
      식별자·저장소 상대 소스 위치·고정 용도와 빈 `현재 현상`·`원하는 변경`
      작성란만 포함함
- [ ] 복사 결과에 실제 IP, Hostname·장비 별칭과 행 값, 사용자명·비밀번호·
      Enable Secret, 설정 입력값, 원본 명령 출력, 로그 내용 또는 로컬 절대
      경로가 없고 외부 전송이 발생하지 않음
- [ ] 실제 물리 F12/Fn 키 매핑, 창 포커스 전환, 100%/125%/150% 배율, 고대비
      테마, 다중 모니터, Windows 트레이와 조직 클립보드 정책에서 각각 검수함

Fn Lock, 제조사 단축키, Windows 셸·트레이 표면과 조직 클립보드 정책 검증을
대체하지 않습니다.

## 트레이와 알림

- [ ] 트레이 아이콘으로 창 열기·숨기기·종료가 정상임
- [ ] X 버튼은 트레이 사용 가능 시 창만 숨기고 감시를 계속함
- [ ] 트레이 사용 불가 환경에서 X 버튼이 안전한 종료를 요청함
- [ ] Windows 알림 테스트와 알림음 테스트가 정책 허용 환경에서 동작함
- [ ] 신규 장애 즉시 알림과 같은 IP/원인의 중복 방지가 정상임
- [ ] 반복 알림 사용 시 설정 간격 전에 반복되지 않음
- [ ] `알림 확인` 후 반복은 중지되지만 감시는 계속됨
- [ ] 복구 알림 설정에 따라 복구 사건과 알림이 정확히 처리됨
- [ ] 트레이/Windows 알림 비활성 환경에서도 프로그램이 종료되지 않음

## 파일, 로그와 종료

- [ ] `%LOCALAPPDATA%\ArubaMiniDashboard`에 설정, DB와 로그가 생성됨
- [ ] `app.db`에 원본 명령 출력과 credential blob이 없음
- [ ] 기본 키, `NOT NULL`/`CHECK`, 필수 인덱스 열·정렬 순서 또는 partial index
      조건이 손상된 SQLite를 정상 schema로 오인하지 않고 자동 점검을 중지함
- [ ] 저장 JSON의 256KiB·깊이 32·노드 20,000개 경계와 중복 키, 비유한 수,
      잘못된 시간·자료형을 실패 안전하게 거부함
- [ ] password·secret·authorization·credential blob·private key·API key 의미의
      snake_case, kebab-case, camelCase 필드가 설정과 SQLite payload에 저장되지 않음
- [ ] 일반 로그에 장비 명령 원문과 비밀번호·Enable Secret이 없음
- [ ] `Authorization: Bearer ...`와 `Authorization: Basic ...`의 scheme 뒤 값
      전체가 로그에서 마스킹되며 다음 정상 필드는 보존됨
- [ ] 로그 파일 잠금·쓰기 실패 시 마스킹 전 record 본문을 stderr에 다시 출력하지 않음
- [ ] SSH 디버그를 켜고 끌 수 있으며, 기록은 제한된 마스킹 excerpt임
- [ ] 일반 모드의 일반/SSH 디버그 로그가 파일당 5MB, 백업 최대 5개로 회전함
- [ ] 저사양 모드의 일반/SSH 디버그 로그가 파일당 2MB, 백업 최대 2개로 회전함
- [ ] 활성 장애와 확인 대기 상태는 정리되지 않으며 종료 장애, 일반 사건,
      확인 완료 Connection-Type 변화와 Failover 이력은 각 테이블에서 최근
      180일·최대 10,000건으로 제한됨
- [ ] 외부 SQLite 쓰기 잠금 중에도 설정 미러 쓰기가 0.5초 안에 실패 안전하게
      반환되고 창 입력과 화면 갱신이 계속됨
- [ ] 설정 저장 실패나 SQLite lock에도 현재 화면이 종료되지 않음
- [ ] 종료 중 점검 작업을 취소하고 SSH 세션을 닫음
- [ ] 종료 후 백그라운드 프로세스가 남지 않음

검수 결과에는 화면 캡처, SHA-256, Windows/ArubaOS 버전, 비식별 fixture와
실패 시 사용자 표시 문구·오류 코드를 첨부하십시오. 비밀번호, SSH 개인키,
실제 운영 IP/Hostname과 원본 출력은 승인 없이 증거 파일에 포함하지 마십시오.
